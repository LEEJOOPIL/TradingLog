# SPEC-ASSET-002 — 자산 심볼 입력 필드 통합 (자동 판별 단일 입력)

## 1. 배경 및 목적

SPEC-PRICE-001이 `AssetTypes` 시트 B열에 바이낸스 심볼을, SPEC-PRICE-002가 C열에 금속시세 심볼을 각각 도입했다. 두 SPEC 모두 자기 범위에서는 옳은 설계였지만, 결과적으로 웹앱 자산 관리 패널의 자산 한 줄에 **입력 필드 2개 + 저장 버튼 2개**가 나란히 놓이게 됐다(`Index.html` `renderAssetManager()`).

사용자는 이 화면을 혼란스럽다고 판단했다 — 자산 하나에 심볼 칸이 왜 둘인지, 어느 쪽에 무엇을 넣어야 하는지가 화면만 봐서는 알 수 없다.

이 SPEC은 **자산 한 줄당 심볼 입력 필드를 하나로 줄인다.** 입력된 값의 형태를 저장 시점에 시스템이 스스로 판별해 올바른 열에 기록한다. 사용자는 "이게 어느 API용 심볼인지"를 알 필요가 없다.

## 2. 범위 결정 사항 (명시)

### 2.1 판별 방식 — 자동 판별, 종류 선택 UI 없음

두 가지 선택지가 있었다.

| 안 | 내용 | 판정 |
|----|------|------|
| **채택** — 자동 판별 | 입력값이 `XAU`/`XAG`면 금속시세, 그 외는 바이낸스 | 사용자가 아무것도 고르지 않아도 된다 |
| 기각 — 종류 선택 드롭다운 | 입력 필드 옆에 "바이낸스 / 금속시세" 선택 | 필드를 하나로 줄이는 대신 선택 UI가 생겨, 사용자 입장에서 결정할 것이 여전히 둘이다 |

사용자가 자동 판별을 명시적으로 선택했다. 판별 규칙은 대소문자를 무시하고 `XAU`(금) 또는 `XAG`(은) 두 값에만 반응한다 — 이 두 값은 현재 이 프로젝트가 gold-api.com에서 조회할 수 있는 전부다(SPEC-PRICE-002 §6.1, 백금·팔라듐은 제외 범위).

### 2.2 자산 하나당 심볼은 하나 — 의도된 단순화

이 설계를 채택하면 한 자산은 구조적으로 **바이낸스 심볼 또는 금속시세 심볼 중 하나만** 가질 수 있다. 새 값을 저장하면 반대쪽 열이 비워지기 때문이다.

사용자가 이 단순화를 받아들였다. 근거: 한 자산이 암호화폐이면서 동시에 귀금속인 경우는 정상 사용에서 발생하지 않는다(SPEC-PRICE-002 §2.3이 이미 같은 판단을 기록해 뒀다). 두 심볼을 동시에 가질 수 있게 열어 두는 것은 실제 필요 없는 자유도이며, 그 자유도가 바로 지금의 입력 필드 2개를 만들었다.

**시트 열 구조는 바꾸지 않는다.** A(자산명) / B(바이낸스 심볼) / C(금속시세 심볼) 3열을 그대로 유지한다 — 열을 합치면 "이 문자열이 어느 API용인지 형식으로 추측"하는 문제가 저장 계층까지 내려온다(SPEC-PRICE-002 §2.3 기각안과 동일한 이유). 판별은 **쓰기 시점 한 번**만 일어나고, 저장된 뒤에는 열 위치 자체가 종류를 말해 준다.

### 2.3 조회 우선순위 로직은 손대지 않는다

`Index.html` `fetchAssetPrice(cat)`는 지금 "바이낸스 심볼이 있으면 바이낸스, 없고 금속 심볼이 있으면 gold-api"로 분기한다(SPEC-PRICE-002 REQ-015). 이 SPEC 이후로는 두 심볼이 동시에 채워질 일이 없으므로 이 우선순위 분기는 실질적으로 발동하지 않게 되지만, **코드는 그대로 둔다.**

이유는 두 가지다. 첫째, 이 SPEC 이전에 저장된 데이터에는 두 열이 모두 채워진 행이 실제로 존재할 수 있고(§2.4), 그 행에는 이 분기가 여전히 유일한 방어선이다. 둘째, 조회 경로를 건드리면 이 SPEC의 위험 범위가 "심볼 저장"에서 "시세 조회 전체"로 넓어진다 — 얻는 것 없이 회귀 위험만 늘어난다.

### 2.4 기존 이중 등록 행 — 건드리지 않고, 다음 저장 때 정리

이 SPEC 이전에 사용자가 한 자산에 B·C 두 심볼을 모두 등록해 뒀을 수 있다. 이런 행의 처리 방침:

- **일괄 마이그레이션을 하지 않는다.** 웹앱을 새 버전으로 배포한다고 해서 기존 시트 데이터를 자동으로 정리하지 않는다 — 사용자가 요청하지 않은 데이터 변경은 하지 않는다는 원칙이며, 실패 시 되돌릴 방법이 없는 종류의 작업이다.
- **표시는 바이낸스 심볼을 우선한다.** 통합된 단일 입력 필드에는 B열 값이 보인다. 근거: 기존 조회 우선순위(§2.3)가 바이낸스를 먼저 보므로, 화면에 보이는 값과 실제로 조회에 쓰이는 값이 일치한다.
- **사용자가 그 자산의 심볼을 다음에 저장하는 순간 정리된다.** 그때 단일 입력 저장 로직이 작동해 한쪽만 남고 반대쪽이 비워진다.

즉 정리는 자동이되 **사용자의 명시적 저장 동작에 얹혀서만** 일어난다.

### 2.5 서버 함수 — 신규 단일 진입점, 기존 두 함수는 남겨 둔다

신규 함수 `setSymbol(name, symbol)`을 만든다. 기존 `setAssetSymbol(name, symbol)`(B열 전용)과 `setMetalSymbol(name, symbol)`(C열 전용)은 **코드에 그대로 남기되 UI에서 더 이상 호출하지 않는다.**

두 함수의 삭제는 이 SPEC의 범위가 아니다(§6). 삭제는 되돌리기 쉬운 별개의 정리 작업이고, 이 SPEC의 위험 예산은 "저장 시 반대쪽 열을 비우는 판별 로직"이 정확한지에 써야 한다. 삭제 여부는 이 SPEC 완료 후 사용자가 판단한다.

## 3. 요구사항 (GEARS)

### 3.1 서버 — 판별 및 기록

**REQ-001** (Ubiquitous)
The `setSymbol(name, symbol)` 서버 함수 shall 자산명과 심볼 문자열을 받아 심볼 종류를 스스로 판별하고 `AssetTypes` 시트의 알맞은 열에 기록하는 **단일 진입점**으로 동작한다.

**REQ-002** (Event-driven)
**When** 입력 심볼이 앞뒤 공백 제거 후 대소문자를 무시하고 `XAU` 또는 `XAG`와 일치하면, the `setSymbol` shall 해당 자산 행의 **C열에 그 값을 기록하고 B열을 빈 문자열로 비운다**.

**REQ-003** (Event-driven)
**When** 입력 심볼이 비어 있지 않으면서 REQ-002의 금속시세 조건에 해당하지 않으면, the `setSymbol` shall 해당 자산 행의 **B열에 그 값을 기록하고 C열을 빈 문자열로 비운다**.

**REQ-004** (Event-driven)
**When** 입력 심볼이 비어 있거나 공백만으로 이루어져 있으면, the `setSymbol` shall 해당 자산 행의 **B열과 C열을 모두 빈 문자열로 비운다**.

**REQ-005** (Ubiquitous)
The 시트에 기록되는 심볼 값 shall 앞뒤 공백을 제거하고 대문자로 정규화한 형태여야 한다(`xau` → `XAU`, ` btcusdt ` → `BTCUSDT`).

**REQ-006** (Event-detected)
**When** 대상 자산명이 `AssetTypes` 시트에 존재하지 않는 상태가 감지되면, the `setSymbol` shall `{error}` 형태의 JSON 문자열을 반환하고 시트를 **전혀 변경하지 않는다**.

**REQ-007** (Ubiquitous)
The `setSymbol`의 B·C 두 열 기록 shall 단일 `setValues()` 호출 1회로 수행한다 — 열별로 나누어 두 번 쓰지 않는다.

**REQ-008** (Unwanted)
The `setSymbol` shall not `updateAssetDropdown_()`를 호출한다 — 심볼 수정은 자산 목록(A열) 자체를 바꾸지 않으므로 드롭다운 갱신 대상이 아니다(`setAssetSymbol`·`setMetalSymbol`과 동일한 근거).

### 3.2 웹앱 UI — 단일 입력 필드

**REQ-009** (Ubiquitous)
The 자산 관리 패널의 자산 행 shall 자산 하나당 심볼 입력 필드 **1개**와 저장 버튼 **1개**만 렌더한다.

**REQ-010** (Where — 초기 표시값)
**Where** 자산의 B열(바이낸스 심볼)이 비어 있지 않으면 the 통합 입력 필드 shall B열 값을 표시하고, **where** B열은 비어 있고 C열(금속시세 심볼)만 채워져 있으면 C열 값을 표시하며, **where** 두 열이 모두 비어 있으면 빈 값을 표시한다.

**REQ-011** (Ubiquitous)
The 통합 입력 필드의 placeholder shall 두 형식을 모두 예시로 보여 준다(예: `심볼 (예: BTCUSDT, XAU, XAG)`).

**REQ-012** (Event-driven)
**When** 사용자가 통합 입력 필드의 저장 버튼을 클릭하면, the 클라이언트 shall `setSymbol(자산명, 입력값)`을 호출하고 그 응답으로 자산 관리 패널과 현재가 설정 패널을 재렌더한다.

### 3.3 조회 경로 — 불변

**REQ-013** (Unwanted)
The 시세 조회 경로(`fetchAssetPrice`, `fetchBinancePriceClient_`, `fetchGoldApiPriceClient_`)와 "값 가져오기" 버튼의 노출 조건 shall not 이 SPEC에서 변경되지 않는다.

### 3.4 문서

**REQ-014** (Ubiquitous)
The 프로젝트 문서(`CLAUDE.md`) shall 자산 관리 패널의 심볼 입력이 단일 필드 자동 판별 방식임을 반영하도록 갱신한다(sync 단계, manager-docs 소유).

## 4. 제약 조건

| 구분 | 제약 |
|------|------|
| 플랫폼 | Google Apps Script + Google Sheets. 외부 라이브러리 도입 금지 |
| 시트 구조 | `AssetTypes` 시트는 A/B/C 3열 구조를 그대로 유지 — 열 추가·삭제·의미 변경 없음 |
| 시트 API | 심볼 저장은 B·C 단일 `setValues()` 1회(REQ-007). 자산 행 탐색을 위한 A열 읽기 1회는 기존과 동일 |
| 반환 규약 | `setSymbol`은 성공 시 `getPortfolioData()` 결과를, 실패 시 `JSON.stringify({error})`를 반환한다(기존 두 함수와 동일한 규약) |
| 하위 호환 | `getAssetTypes` / `addAssetType` / `deleteAssetType` / `setAssetPrice` / `getPortfolioData` / `readAssetRows_` 시그니처 불변 |
| 데이터 안전 | 기존 시트 데이터에 대한 일괄 변경·마이그레이션 금지(§2.4) |
| 배포 | 코드 변경 후 Apps Script 새 버전 재배포 필요 |

## 5. 성공 기준

- 자산 관리 패널의 각 자산 행에 심볼 입력 필드가 **하나만** 보인다.
- `BTCUSDT`를 입력해 저장하면 시트 B열에 기록되고 C열은 비워진다.
- `XAU`(또는 소문자 `xau`)를 입력해 저장하면 시트 C열에 `XAU`로 기록되고 B열은 비워진다.
- 입력을 비우고 저장하면 B·C 두 열이 모두 비워지고 "값 가져오기" 버튼이 사라진다.
- 저장 직후 "값 가져오기"가 두 종류 심볼 모두에서 기존과 동일하게 동작한다.
- 이 SPEC 이전에 두 열이 모두 채워져 있던 자산은 배포만으로는 변하지 않고, 화면에는 바이낸스 심볼이 보인다.
- 자산 추가·삭제·행 CRUD·요약 계산이 회귀 없이 동작한다.

## 6. 제외 범위 (Exclusions)

아래 항목은 이 SPEC에서 만들지 **않는** 것들이다. 모두 out of scope이며, 별도 SPEC이나 사용자의 명시적 승인 없이 구현에 포함해서는 안 된다.

### Out of Scope — 조회 로직

- `fetchAssetPrice(cat)`의 바이낸스 우선 분기 로직 변경 또는 제거 — §2.3의 근거로 그대로 둔다.
- `fetchBinancePriceClient_` / `fetchGoldApiPriceClient_` 내부 동작 변경.
- "값 가져오기" 버튼의 노출 조건(B열 OR C열) 변경.

### Out of Scope — 데이터 구조

- `AssetTypes` 시트의 열 추가·삭제·통합 — A/B/C 3열 구조 유지.
- 기존 이중 등록 행에 대한 일괄 마이그레이션 스크립트 — §2.4.
- 심볼 유효성의 사전 검증(실제로 바이낸스·gold-api에 존재하는 심볼인지 저장 전에 확인) — 잘못된 심볼은 기존과 동일하게 조회 시점에 오류로 드러난다.

### Out of Scope — 코드 정리

- 기존 `setAssetSymbol` / `setMetalSymbol` 서버 함수 삭제 — §2.5. UI 호출만 끊고 함수는 남긴다.
- `updateAssetDropdown_()` 호출 정책 변경 — 심볼 편집은 여전히 드롭다운을 건드리지 않는다.

### Out of Scope — 기능 확장

- 금·은 외 귀금속(`XPT`·`XPD` 등) 판별 규칙 추가.
- 자산별 심볼 여러 개 등록.
- 심볼 자동 완성·추천 UI.
