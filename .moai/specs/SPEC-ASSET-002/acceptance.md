# SPEC-ASSET-002 — 인수 기준

자동화 테스트 스위트가 없는 프로젝트이므로 모든 시나리오는 **Apps Script 에디터 실행 + 웹앱 실기 조작**으로 검증한다. 각 항목은 참/거짓으로 판정 가능해야 한다.

## §D 인수 시나리오

### AC-001 — 자산 행당 심볼 입력 필드 1개

- **Given** 웹앱이 로드된 상태에서
- **When** 자산 관리 패널을 열면
- **Then** 각 자산 행에 심볼 입력 필드가 **정확히 1개**, 저장 버튼이 **정확히 1개** 보이며, `metalsym-*` id를 가진 요소가 DOM에 존재하지 않는다(브라우저 개발자 도구 요소 검사로 확인).

### AC-002 — placeholder 힌트

- **Given** 심볼이 비어 있는 자산 행에서
- **When** 그 자산의 심볼 입력 필드를 보면
- **Then** placeholder에 바이낸스형과 금속형 예시가 **둘 다** 나타난다(예: `심볼 (예: BTCUSDT, XAU, XAG)`).

### AC-003 — 바이낸스형 심볼 저장

- **Given** `비트코인` 자산의 B·C열이 모두 비어 있는 상태에서
- **When** 통합 입력 필드에 `BTCUSDT`를 입력하고 저장하면
- **Then** `AssetTypes` 시트의 `비트코인` 행 **B열이 `BTCUSDT`이고 C열이 빈 값**이며, 현재가 설정 패널의 `비트코인` 행에 "값 가져오기" 버튼이 나타난다.

### AC-004 — 금속형 심볼 저장 (반대쪽 열 비우기)

- **Given** AC-003 직후 `비트코인` 행의 B열에 `BTCUSDT`가 남아 있는 상태에서
- **When** 같은 입력 필드에 `XAU`를 입력하고 저장하면
- **Then** `비트코인` 행의 **C열이 `XAU`이고 B열이 빈 값**이 된다 — 이전에 저장돼 있던 `BTCUSDT`가 남아 있지 않다.

> 이 시나리오가 이 SPEC의 핵심 방어선이다. "반대쪽 열 비우기"가 빠지면 두 심볼이 동시에 남아 통합 이전 상태로 되돌아간다.

### AC-005 — 소문자 입력 판별 및 대문자 정규화

- **Given** 임의 자산의 심볼이 비어 있는 상태에서
- **When** 입력 필드에 소문자로 `xag`를 입력하고 저장하면
- **Then** 시트 **C열에 `XAG`(대문자)로 기록**되고 B열은 빈 값이며, 화면의 입력 필드에도 `XAG`가 표시된다.

### AC-006 — 앞뒤 공백 제거

- **Given** 임의 자산의 심볼이 비어 있는 상태에서
- **When** 입력 필드에 앞뒤 공백을 포함해 `  ethusdt  `를 입력하고 저장하면
- **Then** 시트 B열에 `ETHUSDT`가 공백 없이 기록된다.

### AC-007 — 빈 값 저장 시 두 열 모두 비우기

- **Given** 어떤 자산에 심볼이 등록돼 "값 가져오기" 버튼이 보이는 상태에서
- **When** 입력 필드를 비우고(또는 공백만 남기고) 저장하면
- **Then** 시트의 **B열과 C열이 모두 빈 값**이 되고, 현재가 설정 패널의 그 자산 행에서 "값 가져오기" 버튼이 사라지며 "적용" 버튼만 남는다.

### AC-008 — 존재하지 않는 자산에 저장 시도

- **Given** `AssetTypes` 시트에 없는 이름 `없는자산`에 대해
- **When** Apps Script 에디터에서 `setSymbol('없는자산', 'XAU')`를 실행하면
- **Then** 반환값이 `error` 키를 가진 JSON 문자열이고, `AssetTypes` 시트에 **행이 추가되지 않으며** 기존 어떤 행의 B·C열도 변경되지 않는다.

### AC-009 — 완전 일치 판별 (부분 일치 오판 없음)

- **Given** 임의 자산의 심볼이 비어 있는 상태에서
- **When** 입력 필드에 `XAUUSDT`를 입력하고 저장하면
- **Then** **B열(바이낸스)에 `XAUUSDT`가 기록**되고 C열은 빈 값이다 — `XAU`로 시작한다는 이유로 금속시세로 판별되지 않는다.

### AC-010 — 레거시 이중 등록 행: 배포만으로는 변하지 않는다

- **Given** 스프레드시트에서 손으로 어떤 자산의 B열에 `BTCUSDT`, C열에 `XAU`를 모두 채워 둔 상태에서
- **When** 웹앱을 새로고침해 자산 관리 패널을 열고 **저장 버튼을 누르지 않으면**
- **Then** 통합 입력 필드에 **`BTCUSDT`(B열 값)가 표시**되고, 시트의 B·C 두 값은 **하나도 변하지 않는다**.

### AC-011 — 레거시 이중 등록 행: 저장 시 정리

- **Given** AC-010의 이중 등록 상태에서
- **When** 그 자산의 심볼 입력 필드에 `XAU`를 입력하고 저장하면
- **Then** C열이 `XAU`, **B열이 빈 값**이 되어 한쪽만 남는다.

### AC-012 — 조회 회귀 없음: 바이낸스 경로

- **Given** AC-003으로 `비트코인`에 `BTCUSDT`가 등록된 상태에서
- **When** 현재가 설정 패널에서 `비트코인` 행의 "값 가져오기"를 클릭한 뒤 "적용"을 클릭하면
- **Then** 입력 필드가 0보다 큰 유한한 숫자로 채워지고, "적용" 후 `비트코인` 행들의 시트 F열이 그 값으로 갱신되며 요약 카드가 재계산된다 — SPEC-PRICE-001과 동일한 동작.

### AC-013 — 조회 회귀 없음: 금속시세 경로

- **Given** `금`에 `XAU`가 등록된 상태에서
- **When** `금` 행의 "값 가져오기"를 클릭한 뒤 "적용"을 클릭하면
- **Then** 입력 필드가 0보다 큰 유한한 숫자(소수점 둘째 자리 이하)로 채워지고, "적용" 후 시트 F열이 갱신된다 — SPEC-PRICE-002와 동일한 동작.

### AC-014 — 자산 CRUD 회귀 없음

- **Given** 웹앱이 로드된 상태에서
- **When** 자산 관리 패널로 새 자산 `백금`을 추가한 뒤 삭제하면
- **Then** 추가 직후 모달 자산구분 드롭다운과 현재가 설정 패널에 `백금`이 나타나고(심볼 입력 필드도 1개만 딸려 나온다), 삭제 후 사라진다.

### AC-015 — 문서 갱신

- **Given** 구현이 완료된 상태에서
- **When** `CLAUDE.md`의 자산 관리 패널·`Code.gs` 함수 목록 서술을 확인하면
- **Then** 심볼 입력이 자산당 단일 필드이며 값의 형태로 종류가 자동 판별된다는 내용이 반영되어 있다.

## §D.1 심각도

| 등급 | 항목 | 의미 |
|------|------|------|
| 필수(Blocking) | AC-003, AC-004, AC-007, AC-009, AC-010, AC-012, AC-013, AC-014 | 하나라도 실패하면 완료 불가 |
| 중요(Major) | AC-001, AC-005, AC-008, AC-011 | 실패 시 원인 규명 후 재작업 |
| 보통(Minor) | AC-002, AC-006, AC-015 | 완료 판정 전 반드시 해소하되 순서는 유연 |

**AC-004가 이 SPEC의 핵심 방어선이다** — 반대쪽 열을 비우지 않으면 통합의 전제(자산 하나당 심볼 하나)가 무너져 이전 상태로 되돌아간다.

**AC-010은 데이터 안전 방어선이다** — 사용자가 요청하지 않은 시트 변경이 배포만으로 일어나지 않는지 판정한다.

**AC-009는 판별 규칙 오판 방어선이다** — 부분 일치로 구현하면 여기서 걸린다.

## §D.3 간접 검증

다음은 직접 재현이 어려워 코드 검토로 확인한다.

| 항목 | 확인 방법 |
|------|-----------|
| 시트 쓰기 1회(REQ-007) | `setSymbol` 안의 `setValue`/`setValues` 호출이 정확히 1회이며 `getRange(행, 2, 1, 2)` 형태로 B·C를 함께 쓰는지 코드 리뷰 |
| 판별 완전 일치(REQ-002) | 판별 조건이 `=== 'XAU' \|\| === 'XAG'` 형태의 완전 일치인지, `startsWith`/`includes`/부분 정규식이 아닌지 코드 리뷰 |
| 조회 경로 불변(REQ-013) | `git diff`에 `fetchAssetPrice` / `fetchBinancePriceClient_` / `fetchGoldApiPriceClient_` / `renderPricePanel`의 버튼 노출 조건 변경이 없는지 확인 |
| 마이그레이션 부재 | 배포 코드 어디에도 기존 행의 B·C를 일괄 수정하는 로직이 없는지 코드 리뷰(spec.md §2.4) |
