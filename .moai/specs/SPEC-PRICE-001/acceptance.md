# SPEC-PRICE-001 — 인수 기준

자동화 테스트 스위트가 없는 프로젝트이므로 모든 시나리오는 **Apps Script 에디터 실행 + 웹앱 실기 조작**으로 검증한다. 각 항목은 참/거짓으로 판정 가능해야 한다.

## §D 인수 시나리오

### AC-001 — 심볼 열 프로비저닝 (신규 시트)

- **Given** `AssetTypes` 시트가 없는 상태에서
- **When** `initSheet()`를 실행하면
- **Then** `AssetTypes` 시트가 생성되고 B1 셀에 `바이낸스 심볼`이 굵게 표시되며, `비트코인`/`이더리움`/`솔라나` 행의 B열에 각각 `BTCUSDT`/`ETHUSDT`/`SOLUSDT`가 채워지고 `금`/`은`/`USDT`/`USDC` 행의 B열은 비어 있다.

### AC-002 — 심볼 열 프로비저닝 (기존 시트, 멱등)

- **Given** A열에만 자산명이 있는 기존 `AssetTypes` 시트에서
- **When** 헤더 프로비저닝 경로를 두 번 연속 실행하면
- **Then** B1에 `바이낸스 심볼` 헤더가 한 번만 기록되고, 기존 A열 자산명은 하나도 변경·삭제되지 않으며, 두 번째 실행이 첫 번째 결과를 덮어쓰지 않는다.

### AC-003 — `getAssetTypes()` 시그니처 불변

- **Given** B열에 심볼이 채워진 `AssetTypes` 시트에서
- **When** Apps Script 에디터로 `getAssetTypes()`를 실행하면
- **Then** 반환값이 문자열 배열(`string[]`)이며 각 요소가 자산명 문자열이다 — 객체 배열이 아니다.

### AC-004 — 자산 CRUD 회귀 없음

- **Given** 웹앱이 로드된 상태에서
- **When** 자산 관리 패널로 새 자산 `XRP`를 추가한 뒤 삭제하면
- **Then** 추가 직후 모달 자산구분 드롭다운과 현재가 설정 패널에 `XRP`가 나타나고, 시트 B열 데이터 검증 목록에도 `XRP`가 포함되며, 삭제 후 세 곳 모두에서 사라진다.

### AC-005 — 심볼 등록

- **Given** `XRP` 자산이 심볼 없이 존재하는 상태에서
- **When** 자산 관리 패널에서 `XRP`의 심볼을 `XRPUSDT`로 저장하면
- **Then** `AssetTypes` 시트의 `XRP` 행 B열이 `XRPUSDT`가 되고, 현재가 설정 패널의 `XRP` 행에 "값 가져오기" 버튼이 나타난다.

### AC-006 — 존재하지 않는 자산에 심볼 등록 시도

- **Given** `AssetTypes` 시트에 없는 이름 `없는자산`에 대해
- **When** `setAssetSymbol('없는자산', 'BTCUSDT')`를 실행하면
- **Then** 반환값이 `error` 키를 가진 JSON 문자열이고, `AssetTypes` 시트에 행이 추가되지 않는다.

### AC-007 — 버튼 노출 조건 (심볼 있음)

- **Given** `비트코인`에 `BTCUSDT`가 등록된 상태에서
- **When** 웹앱을 새로고침하면
- **Then** 현재가 설정 패널의 `비트코인` 행에 "값 가져오기"와 "적용" 버튼이 **둘 다** 보인다.

### AC-008 — 버튼 비노출 조건 (심볼 없음)

- **Given** `금`의 B열 심볼이 비어 있는 상태에서
- **When** 웹앱을 새로고침하면
- **Then** 현재가 설정 패널의 `금` 행에는 "적용" 버튼만 있고 "값 가져오기" 버튼이 **없으며**, 기존과 동일하게 숫자를 직접 입력해 "적용"할 수 있다.

### AC-009 — 조회 성공 (Apps Script 실환경)

- **Given** `비트코인`에 `BTCUSDT`가 등록된 상태에서
- **When** 웹앱에서 `비트코인` 행의 "값 가져오기"를 클릭하면
- **Then** `비트코인`의 현재가 입력 필드가 0보다 큰 유한한 숫자로 채워지고, 오류 표시는 나타나지 않으며, 버튼이 정상 상태로 복귀한다.

> 이 시나리오는 **Apps Script 실행 환경에서** 확인해야 한다. 로컬 `curl` 성공은 대체 증거가 아니다(research.md §3 E5).

### AC-010 — 조회는 시트를 변경하지 않는다

- **Given** `비트코인` 보유 행들의 F열(현재가) 값을 기록해 둔 상태에서
- **When** "값 가져오기"만 클릭하고 "적용"은 누르지 않으면
- **Then** 스프레드시트의 해당 F열 값이 **하나도 변하지 않고**, 웹앱 테이블의 수익률 표시와 요약 카드 값도 클릭 전과 동일하다.

### AC-011 — 2단계 확인 흐름 완결

- **Given** AC-009로 입력 필드에 가격이 채워진 상태에서
- **When** 같은 행의 "적용" 버튼을 클릭하면
- **Then** `비트코인` 자산의 모든 행 F열이 그 값으로 갱신되고, 요약 카드의 총 평가금액·종합 수익률이 재계산된다.

### AC-012 — 조회 실패: 잘못된 심볼

- **Given** 임의 자산에 심볼 `NOSUCHPAIR`를 등록한 상태에서
- **When** 해당 행의 "값 가져오기"를 클릭하면
- **Then** 그 행에 인라인 오류 표시가 나타나고, 현재가 입력 필드가 **빈 값**이며, 이전 값이나 대체 값이 채워지지 않고, 시트 F열도 변경되지 않는다.

### AC-013 — 조회 실패: 심볼 미등록 방어

- **Given** 심볼이 비어 있는 자산명 `금`에 대해
- **When** `fetchBinancePrice('금')`을 Apps Script 에디터에서 직접 실행하면
- **Then** 반환값이 `error` 키를 가진 JSON 문자열이며 외부 HTTP 호출이 발생하지 않는다.

### AC-014 — `setAssetPrice` 미호출 확인

- **Given** 웹앱 개발자 도구 네트워크/콘솔을 관찰하는 상태에서
- **When** "값 가져오기"만 클릭하면
- **Then** 서버 호출은 `fetchBinancePrice` 1건뿐이고 `setAssetPrice` 호출이 발생하지 않는다.

### AC-015 — 문서 정책 일치

- **Given** 구현이 완료된 상태에서
- **When** `CLAUDE.md`와 `.moai/project/tech.md`의 가격 소스 서술을 확인하면
- **Then** "외부 API 사용 안 함"이라는 문장이 남아 있지 않고, 수동 입력이 기본이며 심볼이 등록된 자산은 바이낸스 조회를 보조로 쓴다는 내용으로 갱신되어 있다.

### AC-016 — 조회 값은 소수점 둘째 자리까지

- **Given** `비트코인`에 `BTCUSDT`가 등록된 상태에서
- **When** "값 가져오기"를 클릭하면
- **Then** 현재가 입력 필드의 값이 **소수점 둘째 자리 이하**이며(예: `76258.01`), `76258.01000000` 같은 뒤따르는 0도, `76258.0100000001` 같은 부동소수점 잡음도 나타나지 않는다.

판정 기준(둘 다 만족해야 통과):

1. `String(v)`에 소수점이 있으면 소수부 길이가 2 이하다.
2. `Math.abs(v - parseFloat(원본문자열)) < 0.01`이다.

> **절반 지점 방향은 판정하지 않는다.** research.md §7.2 실측에 따르면 `Math.round(x*100)/100`과 `Number(x.toFixed(2))`는 `2.675`·`1.115` 같은 값에서 서로 다른 결과를 내며, **어느 쪽도 십진 직관을 보장하지 못한다**(`1.005`는 두 방식 모두 `1`이 된다). 이는 반올림 방식의 결함이 아니라 십진 리터럴이 이진으로 정확히 표현되지 않는 데서 오는 것이므로, 특정 방향을 인수 조건으로 못 박지 않는다. 최대 오차는 0.01 USD다.

### AC-017 — 1센트 미만 자산의 0 붕괴 차단

- **Given** 임의 자산에 심볼 `SHIBUSDT`(실측 가격 `0.00000530`)를 등록한 상태에서
- **When** 해당 행의 "값 가져오기"를 클릭하면
- **Then** 현재가 입력 필드에 `0`이 채워지지 **않고**, 인라인 오류 표시가 나타나며 입력 필드는 빈 값으로 남는다.

이 항목이 막는 것: `0`이 채워진 채 사용자가 "적용"을 누르면 F열이 0이 되어 수익률이 -100%로 계산된다. 조용히 잘못된 값을 만드는 경로다.

### AC-018 — 수동 입력 정밀도 불변

- **Given** 심볼이 없는 자산 `금`의 현재가 입력 필드에서
- **When** `2345.678901`을 직접 타이핑하고 "적용"을 클릭하면
- **Then** 시트 F열에 `2345.678901`이 반올림 없이 그대로 기록된다 — 조회 경로의 둘째 자리 규칙이 수동 입력에 적용되지 않는다.

같은 확인을 심볼이 **있는** 자산(`비트코인`)에서도 수행한다: 조회를 거치지 않고 직접 타이핑한 값은 역시 반올림되지 않아야 한다. 두 입력 경로가 같은 필드를 공유하더라도 분리되어 있음을 확인하는 항목이다.

| 등급 | 항목 | 의미 |

| 중요(Major) | AC-001, AC-002, AC-005, AC-007, AC-008, AC-013, AC-016 | 실패 시 원인 규명 후 재작업 |

**AC-010과 AC-014가 이 SPEC의 핵심 방어선이다** — 사용자가 확정한 2단계 확인 흐름이 지켜지는지를 직접 판정한다.

**AC-017과 AC-018을 필수로 둔 이유**: 둘 다 "조용히 잘못된 값이 시트에 들어가는" 경로를 막는다. AC-017은 0 붕괴를, AC-018은 반올림 규칙이 수동 입력까지 침범하는 것을 막는다. AC-016(자릿수 자체)은 표시 품질 문제라 중요 등급이다 — 값이 틀리는 게 아니라 보기 나쁜 것이므로 등급이 한 단계 낮다.
