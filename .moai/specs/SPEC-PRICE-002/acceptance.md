# SPEC-PRICE-002 — 인수 기준

자동화 테스트 스위트가 없는 프로젝트이므로 모든 시나리오는 **Apps Script 에디터 실행 + 웹앱 실기 조작**으로 검증한다. 각 항목은 참/거짓으로 판정 가능해야 한다.

## §D 인수 시나리오

### AC-001 — 금속시세 심볼 열 프로비저닝 (헤더만, 시드 없음)

- **Given** `AssetTypes` 시트에 C열 헤더가 없는 상태에서
- **When** C열 헤더 프로비저닝 경로를 실행하면
- **Then** C1 셀에 `금속시세 심볼`이 기록되고, 어떤 행의 C열에도 값이 자동으로 채워지지 않는다(금·은 포함 — 자동 시드하지 않음, spec.md §2.3).

### AC-002 — 금속시세 심볼 열 프로비저닝 (멱등)

- **Given** C1에 이미 `금속시세 심볼` 헤더가 있는 상태에서
- **When** 헤더 프로비저닝 경로를 두 번 연속 실행하면
- **Then** C1 값이 변하지 않고, A·B열 기존 데이터도 하나도 변경·삭제되지 않는다.

### AC-003 — `getAssetTypes()` 시그니처 불변

- **Given** C열에 심볼이 채워진 `AssetTypes` 시트에서
- **When** Apps Script 에디터로 `getAssetTypes()`를 실행하면
- **Then** 반환값이 여전히 문자열 배열(`string[]`)이며 각 요소가 자산명 문자열이다.

### AC-004 — 자산 CRUD 회귀 없음

- **Given** 웹앱이 로드된 상태에서
- **When** 자산 관리 패널로 새 자산 `백금`을 추가한 뒤 삭제하면
- **Then** 추가 직후 모달 자산구분 드롭다운과 현재가 설정 패널에 `백금`이 나타나고, 삭제 후 사라진다 — SPEC-PRICE-001 AC-004와 동일한 회귀 없음 확인.

### AC-005 — 금속시세 심볼 등록

- **Given** `금` 자산이 심볼 없이 존재하는 상태에서
- **When** 자산 관리 패널에서 `금`의 금속시세 심볼을 `XAU`로 저장하면
- **Then** `AssetTypes` 시트의 `금` 행 C열이 `XAU`가 되고, 현재가 설정 패널의 `금` 행에 "값 가져오기" 버튼이 나타난다.

### AC-006 — 존재하지 않는 자산에 금속시세 심볼 등록 시도

- **Given** `AssetTypes` 시트에 없는 이름 `없는자산`에 대해
- **When** `setMetalSymbol('없는자산', 'XAU')`를 실행하면
- **Then** 반환값이 `error` 키를 가진 JSON 문자열이고, `AssetTypes` 시트에 행이 추가되지 않는다.

### AC-007 — 버튼 노출 조건 (OR — 금속시세 심볼만 있음)

- **Given** `금`에 금속시세 심볼 `XAU`만 등록되고(바이낸스 심볼은 비어 있고) 있는 상태에서
- **When** 웹앱을 새로고침하면
- **Then** 현재가 설정 패널의 `금` 행에 "값 가져오기"와 "적용" 버튼이 **둘 다** 보인다.

### AC-008 — 버튼 비노출 조건 (둘 다 없음)

- **Given** `은`의 B열·C열 심볼이 모두 비어 있는 상태에서
- **When** 웹앱을 새로고침하면
- **Then** 현재가 설정 패널의 `은` 행에는 "적용" 버튼만 있고 "값 가져오기" 버튼이 **없으며**, 기존과 동일하게 숫자를 직접 입력해 "적용"할 수 있다.

### AC-009 — 조회 성공 (실제 배포 환경)

- **Given** `금`에 `XAU`가 등록된 상태에서
- **When** 웹앱에서 `금` 행의 "값 가져오기"를 클릭하면
- **Then** `금`의 현재가 입력 필드가 0보다 큰 유한한 숫자로 채워지고, 오류 표시는 나타나지 않으며, 버튼이 정상 상태로 복귀한다.

> 이 시나리오는 **실제 배포된 웹앱을 브라우저로 열어** 확인해야 한다. 로컬 `curl` 성공(spec.md §2.1)은 대체 증거가 아니다.

### AC-010 — 조회는 시트를 변경하지 않는다

- **Given** `금` 보유 행들의 F열(현재가) 값을 기록해 둔 상태에서
- **When** "값 가져오기"만 클릭하고 "적용"은 누르지 않으면
- **Then** 스프레드시트의 해당 F열 값이 **하나도 변하지 않고**, 웹앱 테이블의 수익률 표시와 요약 카드 값도 클릭 전과 동일하다.

### AC-011 — 2단계 확인 흐름 완결

- **Given** AC-009로 입력 필드에 가격이 채워진 상태에서
- **When** 같은 행의 "적용" 버튼을 클릭하면
- **Then** `금` 자산의 모든 행 F열이 그 값으로 갱신되고, 요약 카드의 총 평가금액·종합 수익률이 재계산된다.

### AC-012 — 조회 실패: 잘못된 심볼

- **Given** 임의 자산에 gold-api.com 심볼 `ZZZ`(존재하지 않음)를 등록한 상태에서
- **When** 해당 행의 "값 가져오기"를 클릭하면
- **Then** 그 행에 인라인 오류 표시가 나타나고, 현재가 입력 필드가 **빈 값**이며, 이전 값이나 대체 값이 채워지지 않고, 시트 F열도 변경되지 않는다.

### AC-013 — 우선순위 규칙: 두 심볼이 모두 등록된 경우

- **Given** 어떤 자산에 바이낸스 심볼(`BTCUSDT`)과 금속시세 심볼(`XAU`)이 **둘 다** 등록된 상태에서
- **When** 해당 행의 "값 가져오기"를 클릭하면
- **Then** 브라우저 개발자 도구 네트워크 탭에서 `api.binance.com`(또는 `data-api.binance.vision`) 호출만 관찰되고 `api.gold-api.com` 호출은 **발생하지 않는다** — 바이낸스 결과만 입력 필드에 채워진다.

### AC-014 — `setAssetPrice` 미호출 확인

- **Given** 웹앱 개발자 도구 네트워크/콘솔을 관찰하는 상태에서
- **When** 금속시세 "값 가져오기"만 클릭하면
- **Then** `setAssetPrice` 서버 호출이 발생하지 않는다(SPEC-PRICE-001 AC-014와 동일한 확인, 금속시세 경로에도 적용).

### AC-015 — 문서 정책 갱신

- **Given** 구현이 완료된 상태에서
- **When** `CLAUDE.md`의 가격 소스 서술을 확인하면
- **Then** 금·은에 gold-api.com 조회를 보조로 쓸 수 있다는 내용이 반영되어 있다.

### AC-016 — 조회 값은 소수점 둘째 자리까지

- **Given** `금`에 `XAU`가 등록된 상태에서
- **When** "값 가져오기"를 클릭하면
- **Then** 현재가 입력 필드의 값이 **소수점 둘째 자리 이하**이며, 부동소수점 잡음(예: `4633.6000980001`)이 나타나지 않는다.

판정 기준(둘 다 만족해야 통과):

1. `String(v)`에 소수점이 있으면 소수부 길이가 2 이하다.
2. `Math.abs(v - 원본_price) < 0.01`이다.

### AC-017 — 0 붕괴 차단 (방어적 가드, 아키텍처 일관성 확인용)

- **Given** 응답 `price`가 매우 작은 값(예: `0.001`)이 되도록 임의 심볼을 등록할 수 있다면(가능한 테스트 심볼이 없다면 코드 리뷰로 대체)
- **When** 해당 행의 "값 가져오기"를 클릭하면
- **Then** 현재가 입력 필드에 `0`이 채워지지 **않고**, 인라인 오류 표시가 나타나며 입력 필드는 빈 값으로 남는다.

> gold-api.com이 취급하는 금·은 시세는 통상 두 자릿수 이상이라 이 경로가 실사용 중 자연스럽게 트리거될 가능성은 낮다. 실제 응답으로 재현이 어려우면 §D.3 간접 검증(코드 리뷰)으로 대체한다.

### AC-018 — 수동 입력 정밀도 불변

- **Given** 심볼이 없는 자산에서
- **When** 현재가 입력 필드에 `4567.891234`를 직접 타이핑하고 "적용"을 클릭하면
- **Then** 시트 F열에 `4567.891234`가 반올림 없이 그대로 기록된다 — 조회 경로의 둘째 자리 규칙이 수동 입력에 적용되지 않는다.
